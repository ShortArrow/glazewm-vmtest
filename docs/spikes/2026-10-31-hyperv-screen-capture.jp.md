# スパイク: Hyper-Vのサムネイルにゲスト画面のどこが写るか

- 日付: 2026-10-31
- スパイク: docs/ROADMAP.jp.mdの「ゲスト画面のキャプチャ」のうちHyper-Vの分。QEMUの`screendump`は扱っていない
- ホストとゲスト: docs/spikes/2026-10-31-hyperv-wmi-control.jp.mdと同じ。`daemon-task`に戻して起動し、ユーザー`fixture`が自動ログオンした状態

## 方法

Hyper-VのホストでSSH経由で`Msvm_VirtualSystemManagementService.GetVirtualSystemThumbnailImage`を呼んだ。引数はゲストの実体の`Msvm_VirtualSystemSettingData`と幅・高さである。返った`ImageData`をRGB565として読み、PNGに保存した。Hyper-Vの合成ディスプレイの解像度は、ゲストの`Msvm_VideoHead`で調べた。

ゲストのディスプレイは2台ある。1024×768のMicrosoft Hyper-V Videoと、800×600のVirtual Display Driverである。

RDPの部分では、ゲストでリモートデスクトップをオンにした（`fDenyTSConnections` = 0）。ファイアウォールの規則は有効にしていないので、3389番はゲストのループバックでは応答し、LANからは応答しなかった。クライアントはFreeRDP 3.32.1（Ubuntu 24.04のアーカイブの`xfreerdp3`、パッケージ`3.32.1+dfsg-0ubuntu0.24.04.1`）で、コンテナ内のXvfbの上で動かした。ゲストの`127.0.0.1:3389`へのSSHのポート転送を通し、`fixture`として1280×800で接続した。セッションはゲストで`qwinsta`で調べた。

サムネイルは4つの状態で撮った。RDPの前、RDPの接続中、クライアントを終了させた後、SYSTEMとしてスケジュールタスクから`tscon 1 /dest:console`を実行した後である。

## 観察

| 指定したサイズ | 結果 |
|---|---|
| 640×480 | 46ミリ秒で返った。614 404バイトで、デスクトップを縮小した画像 |
| 1024×768（合成ディスプレイと同じ） | 77〜99ミリ秒で返った。1 572 868バイト |
| 1280×800、1600×900、1600×1000、1920×1200 | 4〜5ミリ秒で、戻り値32775で拒否された |

| 状態 | セッション（`qwinsta`） | サムネイル |
|---|---|---|
| RDPの前 | `console`のセッション1、`fixture`、Active | タスクバーのあるデスクトップ |
| RDPの接続中 | `rdp-tcp#0`のセッション1、`fixture`、Active。`console`のセッション3、Conn | 時計のあるロック画面 |
| RDPのクライアントを終了させた後 | セッション1はDisc。`console`のセッション3、Conn | 接続中と同じロック画面 |
| `tscon 1 /dest:console`の後 | `console`のセッション1、`fixture`、Active | タスクバーのあるデスクトップ |

サムネイルにVirtual Display Driverのディスプレイが写ったことはなく、APIにディスプレイを選ぶ引数もない。

## 設計への影響

- サムネイルに写るのはHyper-Vの合成ディスプレイだけで、大きさはそのディスプレイの解像度までである。モニターのシナリオで足したり外したりするのは、ゲスト内のドライバーが足すディスプレイであり、サムネイルには写らない。すべてのディスプレイの画像は、セッションの中で撮る必要がある。
- RDPがユーザーのセッションを持っている間と、切断してからセッションをコンソールに戻すまでの間は、サムネイルにはコンソールのロック画面が写る。テストを実行しているセッションは写らない。それでも、コンソールがロック画面なのかデスクトップなのかは見分けられる。
- SYSTEMとして`tscon <セッション> /dest:console`を実行すると、ホストからの入力なしで、切断されたセッションがコンソールに戻った。
- UbuntuのアーカイブにあるFreeRDPは、ディスプレイなしでXvfbの上で動き、SSHのポート転送を通して、標準入力から渡したパスワードでゲストにログオンできた。ゲストの3389番はLANには閉じたままだった。

## 測っていないこと

- 大きなサムネイルに合わせて、合成ディスプレイの解像度を上げられるかどうか。
- セッションの中での撮影（ゲストデーモンによるもの）と、RDPがセッションを持っている間にそれに何が写るか。
- RDPの接続中と`tscon`の後の、ゲスト内のディスプレイの配置。
- QEMUの`screendump`。
