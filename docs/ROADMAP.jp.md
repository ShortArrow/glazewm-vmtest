# ロードマップ

## 段階計画

| 段階 | 内容 | 完了条件 |
|---|---|---|
| 0 | 技術検証 | 下記の各検証項目について可否と制約が分かっており、段階1の基盤が決まっている |
| 1 | 段階0で決めた基盤で、モニター追加・削除とRDP切断・再接続のシナリオのベースラインを記録する。テスト用ウィンドウはWin32のみ | docs/PRD.jp.mdの受け入れ基準をその基盤で満たす |
| 2 | もう一方のWindows基盤（Hyper-Vまたはdockur/windows）を追加し、同じシナリオを流す | 段階1のシナリオが変更なしで動く |
| 3 | 操作列の無作為生成、反復実行、他のUIフレームワークのテスト用ウィンドウ。あわせて、プロトコルのクレートから生成したJSON Schemaと、すべてのテスト用ウィンドウのアプリケーションが通る適合テスト | 生成した操作列で失敗したものを、記録から再実行できる |
| 4 | Macホスト上のmacOSゲスト（Virtualization.framework、Tartなど）でglazewmを検証する | Apple SiliconのMacホストを入手するまで保留。着手時はまず、macOSゲストで複数ディスプレイとそのホットプラグを再現できるかを検証する |

## 検証項目

### ゲストのセッション

| 項目 | 確かめること |
|---|---|
| 対話セッション | 自動ログオンするユーザーと、ログオン時に起動するゲストデーモンで、そのセッションの中からSUTとテスト用ウィンドウを起動し、トポロジーを読み、画面をキャプチャできるか。UACの確認なしに昇格したウィンドウを起動できるか |
| スナップショットの種類 | Hyper-Vのチェックポイントの種類（標準、運用）のどちらなら、ログオン済みでデーモンが動いているセッションに戻せるか。復元でゲストの時計とディスプレイの状態がどうなるか |

### トポロジーの変更

各手段で、モニターの追加・削除をゲストにホットプラグとして見せられるか、そのときglazewmが受け取るウィンドウメッセージ（`WM_DISPLAYCHANGE`、`SPI_SETWORKAREA`付きの`WM_SETTINGCHANGE`、`DBT_DEVNODES_CHANGED`付きの`WM_DEVICECHANGE`）が実機と同じかを確かめる。

| 手段 | 基盤 | 確かめること |
|---|---|---|
| ゲスト内の仮想ディスプレイドライバー（IddCx） | 全基盤 | ゲスト内のコマンドだけでモニターを追加・削除できるか。ドライバーにテスト署名モードが要るか。Hyper-Vの合成ビデオは出力が1つなので、Hyper-Vでモニター単位の変更ができる手段はこれだけ |
| 仮想GPUのマルチヘッド（virtio-gpu、QXL） | QEMU/KVM | Windowsゲストのドライバーが出力ごとの有効・無効を反映するか |
| ゲスト内での解像度変更 | 全基盤 | ゲストデーモンが行った変更で、ユーザーが変えたときと同じメッセージが出るか。`Set-VMVideo`はHyper-Vゲストが対応する解像度を決めるだけなので、ここでは使えない |
| RDPクライアントのモニター構成（`/multimon`、`/selectedmonitors`、解像度） | 全基盤 | 再接続で異なるトポロジーを与えられるか。ヘッドレスで動くRDPクライアント（FreeRDPなど）で足りるか |
| VNCクライアントの接続・切断 | QEMU/KVM | ゲストのトポロジーが変わらないことを確認できるか |

### RDP、電源、セッション状態

| 項目 | 確かめること |
|---|---|
| RDPによる乗っ取り | RDPクライアントが同じユーザーでログオンしたとき、対話セッションがどうなるか。RDP接続中のトポロジー、切断後のセッションのトポロジー、その後セッションをコンソールに戻す方法（SYSTEMでの`tscon`など） |
| スリープ | どの基盤でゲストをスリープさせて復帰でき、`PBT_APMSUSPEND`/`PBT_APMRESUMEAUTOMATIC`がゲストに届くか |
| ロックとアンロック | ゲストデーモンがセッションをロックできるか。ホストの入力なしにどうアンロックするか |

### 観測

| 項目 | 確かめること |
|---|---|
| 待機時間 | zebarの4秒ごとのモニター検出を踏まえて、落ち着いたと判断する待機時間をどれだけにするか。負荷の強さごとのIPCの制限時間 |
| ゲスト画面のキャプチャ | WMIのサムネイルAPI（Hyper-V）やモニターコマンド`screendump`（QEMU）でゲストの画面を取れるか。RDPセッションが画面を持っている間も取れるか |
| WMIによるHyper-Vの操作 | 起動、停止、スナップショットの作成と復元をWMI（`Msvm_*`クラス）で賄えるか。PowerShellモジュールが必要な操作はどれか |

### 負荷

| 項目 | 確かめること |
|---|---|
| 物理GPUなしでのGPU負荷 | GPUパススルーがないとゲストはCPU上のソフトウェアで描画する。その場合GPU負荷はCPU負荷と区別できるのか。GPU分割（Hyper-VのGPU-P）が必要か |
| 応答しないテスト用ウィンドウ | テスト用ウィンドウのアプリケーションが、メッセージ処理を確実に止め、後で再開できるか |
| ウィンドウの種類 | UIフレームワークごとに、小さなテスト用ウィンドウのアプリケーションで制御プロトコルを実装できるか。ゲストイメージに何が要るか（ランタイム、サイドロード用の証明書）。自作できない種類（UWPのシステムアプリなど）は、どの既存アプリケーションで代用し、そのライセンスでゲストイメージに含められるか |
